# 本机面试助手设计

日期：2026-07-24

## 一、要做什么

做一个独立的 Mac 面试助手。

它使用 QuickRecorder 已有的本机录音能力作为录音底座，包括系统声音、麦克风和分轨录音，但不是给 QuickRecorder 增加一个功能。

面试助手有自己的应用名称、图标、菜单、悬浮窗口和数据目录。QuickRecorder 原来的录屏界面、编辑功能和普通录制流程不放进面试助手。

面试开始后，它同时做四件事：

1. 录音；
2. 把谈话实时转成文字；
3. 根据候选人的回答给出追问建议；
4. 面试结束后生成逐字稿和评价草稿。

支持线上面试和线下面试，主要支持普通话，也支持中英混合和英文。

## 二、怎么使用

平时只需要两个操作：

- 点击“开始面试”；
- 面试结束后点击“停止面试”。

开始后，系统自动完成：

- 启动系统声音和麦克风录音；
- 判断是线上还是线下面试；
- 判断当前使用的语言；
- 启动实时转写；
- 打开提问建议小窗口；
- 保存本场面试记录。

用户不需要每次选择模型、语言、声道或录音格式。

第一次使用时，需要完成一次初始化：

- 授予录屏和麦克风权限；
- 下载本地语音识别模型；
- 测试麦克风。

初始化完成后，以后都可以一键开始。

## 三、面试材料

JD、简历和评价表都不是必填项。

有材料时，可以在面试前或面试过程中拖入。系统会根据材料给出更有针对性的追问。

没有材料时，使用通用评价维度：

- 经历是否真实、一致；
- 候选人本人做了什么；
- 为什么这样决策；
- 最后取得了什么结果；
- 遇到了什么困难；
- 有什么反思和成长。

## 四、线上和线下面试

### 线上面试

- 系统声音通常是候选人；
- 麦克风通常是面试官；
- 两路声音分开处理，说话人区分会比较准确。

### 线下面试

- 两个人的声音通常都来自同一个麦克风；
- 系统在本机进行说话人区分；
- 如果身份标反，可以点击“一键交换说话人”，不用重新转写。

系统会自动判断场景。如果判断错了，可以在小窗口中直接切换，不需要停止录音。

## 五、实时转写

面试助手复用 QuickRecorder 的录音方式。收到音频后，会同时送到两个地方：

```text
音频
 ├─ 保存到录音文件
 └─ 送到本地语音识别
```

语音识别不会堵塞录音。即使识别模型出错，原始录音也要继续保存。

转写分为两种文字：

- 临时文字：很快出现，可能会修改；
- 稳定文字：一句话基本说完后确认，不再随意变化。

提问建议只使用稳定文字，避免根据半句话给出错误建议。

目标速度：

- 稳定文字在说完后约 4 秒内出现；
- 提问建议在说完后约 8 秒内出现。

## 六、提问建议

系统采用“自动提示 + 手动触发”的混合方式。

以下情况可以自动提示：

- 回答结束了；
- 没说清楚本人具体做了什么；
- 没有量化结果；
- 缺少困难、取舍或反思；
- 回答偏离问题；
- 前后说法可能矛盾；
- 某个重要评价维度一直没有证据。

为了减少干扰：

- 每次最多显示三条建议；
- 普通自动提示至少间隔约 15 秒；
- 重复建议会被过滤；
- 可以暂时关闭自动提示，但录音和转写继续。

用户也可以主动点击：

- 深挖；
- 换个角度；
- 查看评价缺口；
- 把当前回答标记为证据。

每条建议都要包含：

- 可以直接问的问题；
- 为什么建议这样问；
- 它依据了哪段原文。

如果证据不足，必须明确写“待确认”，不能假装已经确定。

## 七、模型选择

语音转写和说话人区分始终在本机完成，不上传录音。

面试建议支持三种方式：

1. 本地模型：默认方式，断网也能使用；
2. OpenAI 模型：通过正式 API 接入；
3. 其他兼容模型：配置地址、模型名称和密钥后使用。

日常使用时不需要选择模型。模型只在高级设置中配置一次。

还可以使用“自动”模式：

- 实时建议使用速度快的模型；
- 面试后报告使用质量更高的模型；
- 云端不可用时自动切回本地模型。

如果使用云端模型：

- 默认只发送已经稳定的文字；
- 不上传录音；
- JD 和简历可以选择不发送；
- 界面明确显示“云端分析”；
- API Key 保存在 macOS 钥匙串中。

默认使用本地分析，并在界面显示“本地分析”。

## 八、面试结束后的结果

点击“停止面试”后，先保存录音，再生成：

- 带时间戳和说话人的逐字稿；
- 总评；
- 优势；
- 劣势；
- 风险；
- 已经问过的问题；
- 支持每项评价的原文和时间戳。

系统不会自动给出录用或淘汰决定。

评价默认标记为“需要面试官确认”。证据不足时必须写“待确认”。

## 九、异常怎么办

基本原则：模型出问题不能影响录音。

- 识别速度跟不上：保留录音，必要时标记转写缺口；
- 识别程序崩溃：自动重启，并补转最近的音频；
- 云端超时或断网：自动改用本地模型；
- 麦克风断开：自动切换到系统默认麦克风并提示；
- 说话人标反：一键交换身份；
- 磁盘空间不足：提前提醒，并安全结束录音；
- 应用意外退出：下次启动时恢复已有录音、文字和评价记录；
- 过时的建议晚到：直接丢弃，不再显示。

## 十、数据保存和隐私

每场面试单独保存，包括：

- 录音文件位置；
- 逐字稿；
- 评价证据；
- 面试材料；
- 评价报告。

所有本地数据保存在 Mac 上。

可以删除整场记录。删除时，分别确认是否连同录音一起删除，避免误删。

录音前会显示录音状态和提醒。是否已取得候选人同意，由面试官负责确认。

## 十一、怎样算完成

第一版需要达到以下要求：

1. 一键开始、一键停止；
2. 支持线上和线下面试；
3. 支持普通话、中英混合和英文；
4. 实时显示转写文字；
5. 自动和手动生成追问建议；
6. 每条评价都有原文依据，或者明确标为待确认；
7. 模型或网络故障不影响原始录音；
8. 云端失败后可以自动切回本地；
9. 连续运行 90 分钟不崩溃；
10. 面试结束后生成逐字稿和评价草稿。

## 十二、第一版暂时不做

- 根据视频画面分析表情；
- 自动替面试官向候选人提问；
- 自动做录用或淘汰决定；
- 团队共享和后台管理；
- 日历和招聘系统集成；
- 手机端。
