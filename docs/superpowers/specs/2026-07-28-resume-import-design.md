# 简历导入与联合面试评价设计

## 目标

在现有“流式转写、实时追问、最终评价”基础上增加简历导入：

1. 支持 PDF、Word、TXT、PNG、JPG；
2. 导入后自动生成总评、优势、劣势和风险；
3. 实时追问同时参考简历和面试逐字稿；
4. 最终评价对比简历描述和面试证据；
5. 原始文件和文字提取均在本机处理。

## 用户流程

首页增加一个次要操作“导入简历”，同时接受文件拖入。导入后显示文件名和处理
状态，不增加模型、语言或解析方式选择。

简历处理成功后自动生成初评。初评明确标注“仅根据简历，待面试验证”。用户仍可
直接点击“开始面试”；面试中的建议和结束后的评价会自动使用当前简历。重新导入
会替换当前简历，用户也可清除，避免评价错人。

## 本机解析

`ResumeTextExtractor` 根据文件类型路由：

- PDF：优先使用 PDFKit 提取文本；无有效文本时逐页渲染并 OCR；
- DOC/DOCX：使用 AppKit 文档读取能力转换为纯文本；
- TXT：按 UTF-8 和常见编码读取；
- PNG/JPG/JPEG：使用 Vision 的准确文字识别，识别语言包含简体中文和英文。

解析器输出 `ResumeDocument`，包含原始文件名、提取文字、导入时间和本机副本路径。
原始简历不发送给模型。只有提取后的文字会交给已登录的 Codex。

## 本机保存

当前简历保存在：

```text
~/Library/Application Support/InterviewAssistant/CurrentCandidate/
```

目录保存原始文件副本、`resume.txt`、`resume-metadata.json` 和
`resume-evaluation.md`。重新打开 App 时恢复当前简历。

开始面试时，把简历文字和初评复制到新的场次目录，使每场面试产物可以独立复核。

## 分析接口

分析 Provider 增加三个明确输入：

- 简历初评：仅传入简历文字；
- 实时建议：传入简历文字和最近三分钟逐字稿；
- 最终评价：传入简历文字和完整逐字稿。

初评和最终评价都固定输出：

```text
## 总评
## 优势
## 劣势
## 风险
```

初评不得把简历自述当成已验证事实。最终评价需要区分简历声明与面试证据；两者
不一致、无法验证或关键结果缺少口径时，写入风险并标记“待确认”。不自动作出录用
或淘汰决定。

## 界面

保持一个主要按钮“开始面试/停止并生成评价”。“导入简历”是次要按钮，旁边显示
当前文件名和“替换/清除”。简历初评直接复用现有四段评价界面，标题显示为
“简历初评”；面试结束后标题切换为“本次面试评价”。

处理期间显示“正在读取简历”“正在识别图片文字”或“正在生成简历初评”。失败时
显示黄色警告，不影响录音按钮。

## 错误处理

- 不支持或损坏的文件：保留旧简历并显示错误；
- OCR 无结果：提示无法识别有效文字；
- Codex 不可用：保存简历和提取文字，允许继续面试；
- 简历复制失败：不替换当前简历；
- 录音、转写和简历分析彼此隔离，任何分析失败都不停止录音。

## 测试

- TXT、PDF、DOCX 和图片文字提取；
- 扫描 PDF 自动切换 OCR；
- 不支持文件和空文本错误；
- 初评提示词包含四个章节和“待面试验证”；
- 实时建议和最终评价包含简历上下文；
- 当前简历保存、恢复、替换和清除；
- Controller 导入状态和评价更新；
- Provider 失败时录音流程不受影响。

## 完成标准

用户导入任一支持格式后能看到简历初评；开始面试后建议会引用简历疑点；停止后
生成结合简历与逐字稿的四段评价，并在场次目录保留可复核的简历文字和评价文件。
