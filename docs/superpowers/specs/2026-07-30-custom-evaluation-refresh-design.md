# 自定义要求刷新评价设计

## 目标

简历评价和面试评价都支持重新生成。刷新前允许用户填写本次要求，
例如“重点评价数据能力”或“总评再简短一些”；输入为空时仍按默认规则刷新。

## 交互

- 评价区域统一显示刷新按钮。
- 简历评价按钮显示“刷新评价和问题”，面试评价按钮显示“刷新评价”。
- 点击按钮后弹出简洁输入面板，包含多行要求输入框、“取消”和“刷新”。
- 用户可以不填写要求直接刷新，减少不必要选择。
- 刷新期间禁用重复操作并显示进度。
- 刷新失败时保留原评价并显示错误；成功后覆盖当前显示和本机评价文件。

## 数据流

### 简历评价

输入要求由界面传给 `SessionController`，再传给 `ResumeImportService` 和
分析 Provider。Provider 将要求追加到简历评价提示词中，并继续使用当前简历
生成总评、优势、劣势、风险和五个建议问题。

### 面试评价

输入要求由界面传给 `SessionController`，再由面试评价刷新服务调用当前
`InterviewIntelligencePipeline`。Pipeline 使用本次逐字稿、当前简历和输入要求
重新生成评价，覆盖场次目录中的 `evaluation-report.md`。

## 边界

- 只有已生成评价时才显示刷新按钮。
- 面试进行中不能刷新评价。
- 面试评价刷新必须存在本次逐字稿和场次目录。
- 自定义要求只影响本次刷新，不保存为长期设置。
- 自定义要求不能改变固定输出结构，也不能绕过简历和逐字稿事实约束。

## 测试

- 提示词会包含非空自定义要求，空白要求会被忽略。
- 简历刷新会把要求传给 Provider，并覆盖本机评价。
- 面试刷新会使用现有逐字稿、简历和要求，并覆盖场次评价文件。
- `SessionController` 能分别刷新简历评价和面试评价。
- 刷新失败时保留旧评价并恢复按钮状态。
