# 实时转写反馈修复设计

## 目标

录音过程中立即显示声音是否正在进入，并在候选人或面试官说话时持续展示临时转写，不再等到停止录音后才看到文字。

## 音频活动指示

- `AudioTapHub` 分别记录系统声音和麦克风最近一次收到音频的时间。
- 界面每 500 毫秒查询一次。
- 正在录音且最近 1 秒内收到对应音频时，指示点显示绿色。
- 不再使用环形缓冲区的条目数量判断活动，避免缓冲区满后指示错误变灰。

## 临时转写

- `SpeechRecognitionChannel` 同时处理临时结果和最终结果。
- 临时结果通过新的 assistant event 发送给界面，每个音源只保留一条并原位更新。
- 临时行显示“识别中”样式，与正式逐字稿区分。
- 收到最终结果后移除对应临时行，再按现有逻辑合并和发布正式逐字稿。
- 停止录音时，将仍有内容的临时结果转为正式记录，避免最后一句丢失。

## 数据保存与分析

- 临时结果只用于界面，不写入逐字稿文件，也不触发追问建议。
- 只有最终确认的文字写入 `transcript.jsonl` 并用于建议和最终评价。

## 错误处理

- 临时结果为空时清除界面占位。
- 转写失败时清除该音源临时结果，并保留现有警告提示。

## 验证

- 测试最近音频时间不会因环形缓冲区容量稳定而失效。
- 测试临时结果会更新同一条界面内容，最终结果会替换临时行。
- 完整测试、正式构建和本机实际录音验证。
